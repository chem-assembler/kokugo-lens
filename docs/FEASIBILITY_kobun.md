# 古文への横展開は成立するか — 見極めメモ（2026-08-12）

これは設計書ではない。**「作れるか」ではなく「同じ仕掛けが効くか」だけを判定する**ためのメモ。
結論を先に書き、根拠として実際に走らせたプロトタイプの結果を置く。

## 問い

漢文アプリが成立したのは、**訓点 → 読み順 → 書き下し が機械で閉じたループ**だったから。
だから二重帳簿テストがデータの正しさを人手なしで証明でき、
1セッションで並列に133問まで積んでも、不備がリポジトリに届く前に止まった。
仕掛けはコードではなくこの構造にある。

**古文に同じ構造があるか。あるとすれば、漢文の「返り点」に当たる一点は何か。**

## 答え

**ある。一点は「接続」。**

しかも古文の帳簿は**漢文より1本多い3本**になる。

| | 帳簿 | 内容 | 漢文の対応 |
|---|---|---|---|
| 1 | 表層 | 語形を連結すると原文に戻る | 読み順 → 書き下し |
| 2 | 接続 | 助動詞の接続 ＝ 直前の語の活用形 | （漢文には無い） |
| 3 | 活用 | 活用表 ＋ 活用形 → 語形を**計算で復元できる** | 訓点 → 読み順（`readOrder`） |

帳簿3が効くのが大きい。漢文で `readOrder` が訓点から読み順を計算したように、
古文では**活用表と活用形から語形そのものを計算できる**。
つまり人が手で書いたデータを、機械が独立に再計算して照合できる。

## 根拠（実際に走らせた結果）

竹取物語と土佐日記の冒頭を品詞分解し、わざと1語だけ壊した対照データを混ぜて検査した。

```
○ 通った  taketori-1  竹取の翁といふものありけり  （竹取物語 冒頭）
○ 通った  tosa-1      男もすなる日記といふものを  （土佐日記 冒頭）
○ 弾けた  _対照-接続違い  男もすなる日記
      帳簿3 「す」の連体形は「する」のはずだが、データは「す」
      帳簿2 「なり伝聞」は終止形接続だが、直前「す」は連体形
```

**壊した1語が、独立した2本の帳簿に同時に引っかかった。** これは漢文の二重帳簿より強い。

そして土佐日記の「男も**す**なる」は、**終止形接続だから伝聞推定**（連体形接続なら断定）という
入試最頻出の識別そのもので、それが帳簿2でそのまま機械検証されている。
つまり**学習の核心と検査の核心が同じ場所にある**。漢文で「読み順」がそうだったのと同じ構図。

活用表から語形を計算できることも確かめた。

```
す の未然形 = せ ／ す の終止形 = す ／ す の連体形 = する
あり の連体形 = ある ／ けり の已然形 = けれ ／ む の未然形 = （無し）
```

「む の未然形＝無し」まで出るのが重要で、**存在しない活用形を機械が拒否できる**。

## 名前

「返り点でみる漢文」に対して **「活用でみる古文」**。
返り点が読み順を決めるように、活用形が接続を決め、接続が識別を決める。

## モードの見取り図（漢文の L1〜L6 に対応させた場合）

| | 与えるもの | 操作 | ねらい | 漢文の対応 |
|---|---|---|---|---|
| K1 | 語に切ってある | 各語の品詞をタップ | 用語に慣れる | L1 |
| K2 | 語に切ってある・1箇所空欄 | その活用形を4択 | **学習価値が集中する段** | L2 |
| K3 | 切っていない本文 | 自分で語を切る（品詞分解） | 切れ目が見えるようになる | L3 |
| K4 | 切っていない本文 | 切る＋活用形も入れる | 文法の完成 | L4 |
| K5 | 傍線部つき本文 | 「この『に』は何か」を答える | 入試の実戦形 | L5/句法クイズ |

漢文と同じく **K2 が本命**になる可能性が高い（比例式の①' と同じ構図）。

## 成立を疑うべき点（ここが弱い）

**1. 返り点は「書く」操作、接続は「見抜く」操作。**
これが最大の相違で、いちばんの不安。返り点は生徒が紙に打つ産出操作だから、
タップやドラッグにそのまま乗った。接続は頭の中の識別で、手を動かす対象になりにくい。
→ 対策は **K3（語を切る）を主役にする**こと。切るのは産出操作で、指が動く。
帳簿1（連結すると原文に戻る）がそのまま採点になるので、判定も素直。
**この見立てが外れると、アプリではなく問題集の焼き直しになる。**

**2. 品詞分解には流派差がある。**
「なり」を断定の助動詞と見るか形容動詞の活用語尾と見るか、など。
→ 学校文法（橋本文法）に固定すると最初に決める。揺れは漢文の `acceptable`（訓読の流派差）と
同じ受け皿で処理できる。**ただし漢文の流派差が4問5件で済んだのに対し、古文はもっと出る**と見るべき。

**3. 本文が長い。**
漢文は4〜16字で1問になったが、古文は1文が長い（源氏はとくに）。
→ 「文節2〜5個」など切り出し単位を先に決める必要がある。竹取・伊勢・徒然草・土佐日記の
冒頭はいずれも短く始まるので、初期の題材には困らない。

**4. データ量は漢文より大きい。**
漢文の句法は38型で有限だった。古文は 動詞9種＋形容詞2種＋形容動詞2種＋助動詞28語＋助詞。
有限ではあるが**桁が1つ大きい**。ただし活用表は表であって文章ではないので、
書き切れば終わる種類の仕事。

**5. 入試調査をもう一度やる必要がある。**
`exam-kanbun-sources.md` に相当するものが要る。あれは大きな投資だった。

## 今すぐ作り始めるべきではない理由

技術的には成立する。それでも順序としては**まだ**だと考える。

- 漢文アプリは公開して1日で、**使われているかのデータがまだ無い**。SNS 告知も未着手
- 化学レンズの方針は「アプリは5本キャップ・レンズで束ねる」。国語レンズはいま1本
- 漢文が刺さるかを見ないまま2本目に行くのは land-and-expand の順序が逆

**このメモの値打ちは、漢文の反応を見たあとすぐ動けるようにしておくこと**にある。

## 次の一手（着手するとき）

1. **切り出し単位を決める**（文節2〜5個か、1文か）。ここが決まらないと題材が選べない
2. **活用表を全部書く**（動詞9・形容詞2・形容動詞2・助動詞28）。有限なので機械検査つきで一気に
3. **帳簿3の検査を先に書く**。漢文で `readOrder` とテストを先に書いたのと同じ順序。
   データより先に検査があると、あとは並列レーンで積める（漢文で実証済み）
4. 題材は竹取・伊勢・徒然草・土佐日記の冒頭から。すべてパブリックドメイン

## 付録: 判定に使ったプロトタイプ

`node` でそのまま走る。活用表と数語の辞書、実データ2件と壊した対照1件だけの最小構成。

```js
const KATSUYO = ['未然', '連用', '終止', '連体', '已然', '命令'];
const 活用型 = {
  'ラ変': ['ら','り','り','る','れ','れ'],  'サ変': ['せ','し','す','する','すれ','せよ'],
  'ハ四': ['は','ひ','ふ','ふ','へ','へ'],  'ラ変型': ['ら','り','り','る','れ','れ'],
  '四段型': [null,null,'む','む','め',null]
};
const 語 = {
  'あり': { 語幹:'あ', 型:'ラ変' }, 'す': { 語幹:'', 型:'サ変' }, 'いふ': { 語幹:'い', 型:'ハ四' },
  'けり': { 語幹:'け', 型:'ラ変型', 接続:'連用' },      // 過去
  'なり伝聞': { 語幹:'な', 型:'ラ変型', 接続:'終止' },  // ← 土佐日記「男もすなる」
  'なり断定': { 語幹:'な', 型:'ラ変型', 接続:'体言' },
  'む': { 語幹:'', 型:'四段型', 接続:'未然' }
};
// 帳簿3: 活用表と活用形から語形を計算する
const 語形を計算 = (見出し, 活用形) => {
  const w = 語[見出し], 語尾 = 活用型[w.型][KATSUYO.indexOf(活用形)];
  return 語尾 == null ? null : w.語幹 + 語尾;
};
// 帳簿1: 連結 === 原文 ／ 帳簿2: 助動詞の接続 === 直前の語の活用形
```

完全版は判定時のスクラッチパッドにある（`kobun-probe.js`）。上の抜粋だけでも3本の帳簿は再現できる。
